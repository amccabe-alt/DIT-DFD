What is a Data Flow Diagram?

A DFD shows how data moves through a system. It focuses on where data comes from, what happens to it, where it is stored, and where it goes. It does not show program logic or decision-making in the same way as a flowchart.

BTEC DIT link: Component 3, Learning outcome D includes interpreting and using forms of notation such as data flow diagrams, flowcharts and system diagrams. In an exam, accurate notation, connections/direction of data flow and coverage of the scenario all matter.

Core DFD symbols

Symbol convention used in this resource: external entity/data source or destination = oval; process = rectangle; data store = open-ended store symbol; data flow = labelled directional arrow.

External Entity

A person, organisation or external system that sends data to, or receives data from, the system.

Example: Customer, Supplier, Bank.

Process

Something that transforms, checks, calculates, creates or otherwise handles data.

Use a verb phrase: “Validate login”, “Calculate total”.

Data Store

A place where data is held for later use, such as a database, file or table.

Example: Customer records, Orders database.

Data Flow

A labelled arrow showing data moving from one part of the system to another.

Label with the data, not an action: “payment details”, not “pay”.

Rules students should remember

RuleWhy?
Every arrow needs a direction and useful data label.The examiner must be able to see what data moves and where.
Processes should be actions.A process changes or uses data.
Do not normally connect entity → entity directly.The system needs a process between them.
Do not normally connect store → store directly.A process should move/transform the data.
Read the scenario for nouns and verbs.Nouns often suggest entities/stores/data; verbs often suggest processes.

Diagram tools

Select a symbol, then click the grid. A name box appears inside each symbol so students can type directly into it. Drag the outline/blank area of a symbol to move it freely anywhere on the grid. For a data flow, click the source then the destination. Then type directly into the text box on the arrow to name the data being transferred. Opposite-direction flows are automatically separated so both labels remain readable. If you try to connect entity-to-entity or store-to-store, the system will warn you because a process should normally sit between them.

Hint: Start by identifying the external entity, the process, and any data stores mentioned in the scenario.
